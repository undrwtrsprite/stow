# Deep dives (11) — 2026-10-20

Every claim carries a label. **Observed** = I read it in the cited doc, source, issue or
screenshot today. **Inferred** = my interpretation. **Unverified** = stated by someone else
and not checked. Interaction sequences are **documentary** (from official docs or source),
not timed in a client. **In-client populated testing of every reference is deferred** (no
Minecraft clients on lunapc this phase). Issue counts come from GitHub/Codeberg searches
today. They show which topics get discussion, not how often bugs happen.

Step notation as in `docs/validation/baseline.md`: K key, C click, T typed entry, D drag.

## 1. Chest Tracker (JackFred2; 26.3 port by ponuing) + Where Is It

**Examined via:** CurseForge page (official, read today); GitHub wiki `Usage.md` and
`Memory-Bank-Settings.md` (cloned); Modrinth gallery (main GUI screenshot opened and
inspected); issues in `JackFred2/ChestTracker` (211 total) and `ponuing/ChestTracker`
(52 total, 8 open).
Links: <https://www.curseforge.com/minecraft/mc-mods/chest-tracker>,
<https://github.com/JackFred2/ChestTracker/wiki/Usage>, <https://modrinth.com/mod/chest-tracker-port>,
<https://github.com/ponuing/ChestTracker/issues>.

**Task sequences (Observed, docs):**
- Find a hovered item: hover + **Y** → matching containers highlighted in world = **1 K**.
- Find by name: **`** (grave) opens GUI → T in search → click item → highlight = **2 C/K + T**.
  The search bar accepts `filter:value` (Searchables). Close returns to the previous GUI.
- Switch dimension or Ender Chest: click a key icon on the left rail = 1 C.
- Move the inventory button: drag it. Positions are saved per screen class, and resource
  packs can supply presets for other mods' screens.

**Strengths:** item-first grid with aggregated counts (Observed in screenshot: counts such as
"2k", "64" on each item); hovered-item search key; per-world "memory banks"; IDs obfuscated by
default for streaming (Observed, wiki); integrations hand off to recipe viewers (Observed, CF).
**Recurring complaints (Observed, issues):** data persistence after relog in the 26.3-era
port (#22, 36 comments; #25, 27; #16, 17); in-world container name labels (original #196,
#167; port #56, #49 "still displayed when in F1"); frequent update requests (#287, #305, #93).
**Accessibility:** icon-only toolbar of six buttons (Observed, screenshot). Item counts are
drawn over item icons in a dense 9-wide grid, which Inferred hurts readability at small GUI
scales. No narration notes in the docs (Unverified either way).
**Performance:** "large sizes may cause slowdowns while rendering a large amount of items"
for the 18×12 GUI (Observed, wiki).
**Compatibility boundaries:** needs YACL; port issue #48 "Crashing with Litematica"
(Observed, title only); integrations with REI/JEI/EMI, WTHIT, Shulker Box Tooltip, Litematica
(Observed, CF).
**For Stow:** item-first + hovered-item lookup is the most effective pattern here. Stow
already shows snapshot age, which Chest Tracker's grid does not (Observed, screenshot).

## 2. Mouse Tweaks (YaLTeR)

**Examined via:** CurseForge description (official, read today); issues in
`YaLTeR/MouseTweaks` (197 total, 56 open).
Links: <https://www.curseforge.com/minecraft/mc-mods/mouse-tweaks>, <https://github.com/YaLTeR/MouseTweaks/issues>.

**Task sequences (Observed, docs):** RMB drag puts items repeatedly (1 D); LMB drag with an
item collects the same type (1 D); Shift+LMB drag moves crossed stacks (1 D); wheel over a
stack moves one at a time (scroll); `WheelScrollDirection=2` makes direction depend on
inventory position.
**Strengths:** zero new UI, one gesture per job, behaviour configurable per gesture.
**Complaints (Observed, titles):** "Lag Spikes when opening inventories" (#12, 2018); crashes
with other inventory mods (#131 Nether Chested, #62 Architectury); "[26.3 Fabric] Right
clicking bug" (#220, open); "Is player slot check too primitive" (#214, open).
**Accessibility:** gestures need fine mouse control and are undiscoverable in-game
(Inferred). Configuration is a file, `MouseTweaks.cfg` (Observed); no in-game screen is
documented.
**Compatibility:** works on `GuiContainer`-style screens; API lets mods exclude slots
(Observed).
**For Stow:** Stow already owns Shift-drag modes and has `MixinMouseTweaks`. Who handles a
gesture must be explicit when both mods are installed. Coexistence test deferred.

## 3. Inventory Profiles Next

**Examined via:** official docs site (home and known-issues pages; other doc paths 404 today);
CurseForge page (official); English lang file from the **archived** GitHub mirror
`blackd/Inventory-Profiles` (archived 2025-06-17, so Inferred to approximate current UI
labels); Codeberg issues (50 most-commented fetched).
Links: <https://inventory-profiles-next.github.io/en/>, <https://www.curseforge.com/minecraft/mc-mods/inventory-profiles-next>,
<https://codeberg.org/Inventory-Profiles-Next-Mod/IPN>.

**Task sequences (Observed, lang/docs):** sort = click the overlay **Sort** button (also
"Sort in Columns" and "Sort in Rows" buttons) or press a hotkey; **scroll over the Sort
button to change the sort order**; Move All button whose tooltip lists the modifiers ("Hold X
– include hotbar / move matching only / move only enough to top up"); open config with
**R+C**; optional settings and overlay-editor buttons inside the inventory.
**Strengths:** visible buttons whose tooltips teach the modifiers, so hidden variants are
discoverable at the point of use (Observed text; effect Inferred).
**Complaints (Observed):** config anchor header clipped at GUI scale >2 or tiny windows
(known issues); a Quilt item duplication led to reduced Quilt support (CF warning); top
Codeberg threads are crashes and "Focused Item Type Move Bug" (#288).
**Accessibility:** dense config with nine categories. The earlier lab found the config
screen busy (Observed by the earlier session, not re-checked).
**Compatibility:** client-only; Kotlin + libIPN required; Quilt treated as best-effort.
**For Stow:** a visible Sort control whose tooltip teaches middle-click and the Shift/Ctrl
orders; scroll to change order. The dupe history is a reminder to keep Stow's
conservation guarantees non-negotiable.

## 4. Litematica (Material List)

**Examined via:** CurseForge page (official); source `GuiMaterialList.java` and `en_us.json`
from `sakura-ryoko/litematica` branch `26.3`; Modrinth gallery (Material List screenshot
opened and inspected); issues (291 total).
Links: <https://www.curseforge.com/minecraft/mc-mods/litematica>, <https://github.com/sakura-ryoko/litematica>,
<https://modrinth.com/mod/litematica>.

**Task sequences (Observed, CF + lang):** open main menu (**M**) → Material List (1 K + 1 C);
toggle "Hide available"; per-row **Ignore**; "Info HUD" toggle puts a missing-items
"shopping list" HUD on screen; Write to file / CSV (Shift) / JSON (Alt); Multiplier field.
Config: **M+C**.
**Strengths (Observed, screenshot):** a table with **Item / Total / Missing / Available**
columns; a hover tooltip breaks a total into stacks and shulker boxes (e.g.
"239 = 3 × 64 + 47 = 3.74 SB"); footer total and progress (Done / Missing / Mismatched %).
**Complaints (Observed):** raw-materials output request (#167, 48 comments); "Searching has
gotten really slow ever since the new update" (#406, open); "Searching not triggering on key
press" (#401); keyboard-layout hotkeys (CF FAQ: AZERTY makes M+C into ,+C); a **security
vulnerability notice** for 1.21+ builds on the CF page.
**Accessibility:** numbers are colour-coded but also present as text (Observed), so state
is not colour-only.
**Compatibility:** MaLiLib required; Easy Place may trigger anti-cheat (CF warning).
**For Stow:** adopt the column model (Need / Have / Missing / Sources) and the stack/shulker
breakdown. Stow should not duplicate schematic verification or placement (Litematica's job).

## 5. Litematica Material HUD (small, Fabric 26.3, released today)

**Examined via:** Modrinth description and gallery (12 images; "Highlight all chests" opened
and inspected). No source URL is listed, so source is not examined.
Link: <https://modrinth.com/mod/material-hud>.

**Task sequences (Observed, description):** **Y** shows the material list for the current
layer; **U** marks every remembered container within 96 blocks (configurable to 256) that
holds needed blocks; **Ctrl+U** clears; opening a chest makes the matching slots glow; items
you already carry enough of are skipped; Page Up/Down pages even with a chest open.
**Strengths:** gathering is one keypress from the plan; counts in blocks, stacks and shulker
boxes; the stated range keeps work bounded.
**Overlap with Stow:** high. It remembers containers, highlights sources and lists
materials, but only for Litematica schematics. **Inferred:** Stow must not add a competing
schematic flow. Its distinct value is player-defined projects, imports from pasted lists,
exact components and server-checked operations.
**Complaints/compatibility:** too new for an issue history (no tracker linked); Litematica
required.

## 6. Jade

**Examined via:** CurseForge page (official, default keys); Modrinth gallery titles; issues in
`Snownee/Jade` (631 total).
Links: <https://www.curseforge.com/minecraft/mc-mods/jade>, <https://github.com/Snownee/Jade/issues>.

**Task sequences (Observed, CF):** look at a block → overlay (0 steps); **KP0** config, **KP1**
toggle overlay, **KP2** liquids, **KP3/KP4** recipes/uses with JEI, **KP5 narrate target**.
**Strengths:** zero-step contextual info; explicit narration key; "better accessibility" is a
stated goal; the description says plainly which features need the server side (item storage,
brewing fuel, bees).
**Complaints (Observed):** "Show details keybind overrides vanilla's Sneak" (#116);
"Causing lag with FallingTree" (#639); "Container item list is silently dropped when the
server data exceeds 16 KB" (#824, open, filed yesterday); "Hide names?" (#256).
**For Stow:** say plainly what needs the Companion; add a narration path; bounded payloads
must fail **visibly**, never silently (Stow's companion caps sorting requests at 24 KiB, so
apply the same rule).

## 7. Shulker Box Tooltip

**Examined via:** CurseForge page (official); Modrinth gallery titles; issues in
`MisterPeModder/ShulkerBoxTooltip` (215 total, 34 open); the earlier lab's crash record
(not re-run).
Links: <https://www.curseforge.com/minecraft/mc-mods/shulkerboxtooltip>, <https://github.com/MisterPeModder/ShulkerBoxTooltip/issues>.

**Task sequences (Observed):** hover + **Shift** = compact preview; **Alt+Shift** = full
preview with slot positions; colours follow the box dye; config through Mod Menu.
**Strengths:** two densities (compact list vs. exact slots); optional server part for Ender
Chest data.
**Complaints (Observed):** "the fabric mod menu cannot change the settings" (#16, 48
comments, closed); "Hotkey to freeze preview UI to allow hovering over preview items" (#48);
"Holding CTRL to lock tooltips should be disabled by default" (#261); slot mismatch on
servers (#152, open); "Game freezes … Ender Chest with server integration" (#264, open). The
earlier lab recorded a 5.4.2+26.3 crash before the title screen (Observed by that session).
**For Stow:** Stow shows a 9×3 grid on plain hover and defers to another mod's tooltip
image. Keep that rule, and do not add modifier-locking defaults. Coexistence must be tested
because both hook the same tooltip path (deferred).

## 8. Mod Menu + Controlling (configuration and keybind discovery)

**Examined via:** Mod Menu wiki (`Mods-Screen.md`, `Mod-Search.md`, cloned); Controlling
README; issues in `TerraformersMC/ModMenu` (636 total) and `jaredlll08/Controlling` (143
total); JEI's key-mapping strings as a comparison.
Links: <https://github.com/TerraformersMC/ModMenu/wiki>, <https://github.com/jaredlll08/Controlling>.

**Task sequences (Observed, docs):** Mod Menu: Title/Pause → **Mods** → type name (search
also matches special terms such as `config`) → select → **Configure** = 3 C + T. Controlling:
Options → Controls → Key Binds → type an action or key name → rebind.
**Strengths:** players already look in Mod Menu for settings and in Controls for keys.
JEI labels every binding with a description and a **context** ("a GUI is open", "hovering
over an ingredient") (Observed, JEI `en_us.json`).
**Complaints (Observed):** Mod Menu "Config button not showing on some mods" (#509), "mods
menu button won't show" (#968, #1085); Controlling "Searching for a key could be better"
(#213), "Modifier keys cannot be bound on their own" (#211), "Does not account for GUI scale
setting" (#74).
**For Stow:** Stow's 16 actions are invisible to vanilla Controls and Controlling (baseline
§1.4). Investigate registering them as `KeyMapping`s with categories and context text while
keeping Stow's chord and conflict logic.

## 9. Tom's Simple Storage (terminal)

**Examined via:** `en_us.json` from `tom5454/Toms-Storage` (master); CurseForge page
(official); issues (755 total, 238 open).
Links: <https://github.com/tom5454/Toms-Storage>, <https://www.curseforge.com/minecraft/mc-mods/toms-storage>.

**Task sequences (Observed, lang):** open terminal → type → take. Sort cycles Amount / Name /
Mod / Space efficiency / ID / Type. Search options: **Auto-select search** (the field takes
focus on open), **Keep search** (the query persists between openings), **Sync with JEI/REI**,
"Smart features (may lag)". Terminal stats show all slots, free %, unique items. The search
field has a **narrator label**.
**Strengths:** the two options that remove Stow's re-typing cost (auto-focus and keep query)
are user-selectable; a performance cost is labelled at the option.
**Complaints (Observed):** item quantities shown doubled (#306, #69, #548 with Sophisticated
Storage); "[TPS] The mod can't handle a lot of chests!" (#297); range limits (#269, #807).
**For Stow:** keep the query and focus on open; label options that may cost performance;
treat aggregated counts with care (doubling bugs are the recurring failure in this genre;
Stow's double-chest and duplicate-position handling must be tested).

## 10. WorldEdit (area selection)

**Examined via:** official docs "Selection" page; issues (1,949 total).
Links: <https://worldedit.enginehub.org/en/latest/usage/regions/selections/>, <https://github.com/EngineHub/WorldEdit/issues>.

**Task sequences (Observed, docs):** `//wand` → LC corner 1 → RC corner 2 (2 C after the
wand); `//hpos1/2` for the crosshair at range; `//expand vert` covers full height in one
command; `//expand 10 n,w`; `//size`, `//count`; outlines need a CUI client mod.

**Complaints (Observed):** "//sel extend forgets it was set after arbitrary time" (#2188);
26.3 permission issue (#3033).
**For Stow:** Stow's area claim already uses LC/RC + height. Adapt a one-key "full allowed
height" and a live size readout (Stow shows the box size already). Do not add commands.

## 11. JEI (search and history conventions)

**Examined via:** `en_us.json` (branch `26.3`); GitHub wiki index (cloned); issues (3,902
total).
Links: <https://github.com/mezz/JustEnoughItems>.

**Observed:** key mappings for focus search, clear search, **previous/next search
(history)**, **lookup history**, bookmarks ("Hover over an ingredient and press %s to
bookmark it"), and per-binding description and context strings. Search completion and
matching options exist in config.
**Complaints (Observed):** recent crash reports on inventory open with the 26.3 beta
(#4565, #4568); historical "Search bar; loss of focus / hang" (#649).
**For Stow:** search history (↑ in an empty query recalls the last one) and "hover + key"
lookups are conventions players already know. Stow's `N` (track) and a proposed "hover + key
→ find in storage" follow them.
