## Camera-selected legacy storage claims and UI follow-up — 20 October 2026

The user reported that older storage did not appear under Mine without replacing it, chose an explicit one-time area claim instead of historical-log recovery, then requested a free camera selector and server persistence. The development pair is **1.0.5-test.6+mc26.3**. Historical placers cannot be inferred from ordinary old container data; this feature explicitly assigns unclaimed storage to the requester and skips every pre-existing label, including Shared and operator-visible foreign storage.

The local camera is an unregistered ArmorStand with a free negative local ID, original input/camera/perspective restoration, neutral player input, captured selection keys/mouse buttons and normal mouse-sensitivity look redirected to the camera. It never sends camera movement as player movement. Movement stays in loaded terrain within 64 blocks per axis. Selection has two steps: footprint (left-click corner 1, right-click corner 2 on the targeted block within 32 blocks; with corner 1 set, right-click advances immediately when the footprint is valid, otherwise it stays and shows the reason; Enter also advances; Backspace undoes; the flat box sits at the lower clicked Y) and height (wheel or Up/Down moves the top, Alt moves the bottom, Ctrl steps by 5, clamped to the world and 64 blocks of the character; left-click/Enter confirms, Backspace returns to the footprint, right-click is ignored so a quick second right-click cannot undo or confirm the step it just entered). Escape returns without a selection. The toggle-HUD key (F1) is handled directly because vanilla keybind handling is paused; outlines are drawn from a Hud HEAD hook so they stay visible with the HUD hidden, while the controls panel is a normal HUD element styled like the command palette (tinted menu-list background, grey outline, white actions, grey right-aligned key names, UIIcons mouse symbols; key names from the current bindings). Camera movement reads the bound movement/jump/sneak/sprint keys when they are keyboard bindings and falls back to the defaults otherwise. A moved/dead/replaced player, unexpected screen/camera, dimension change or disconnect ends selection. The original player remains subject to normal server physics. No containers are claimed until the review action is explicitly pressed.

The companion validates the selected box (262,144 positions and 64 blocks per axis maximum), then runs finite jobs with a combined 512-position/eight-container budget per tick, max eight jobs/one per player. It uses `getChunkNow`, skips unloaded positions, private/shared/locked/inaccessible storage and incomplete boundary doubles, and never inspects inventory contents. Cancellation retains completed changes; movement beyond eight blocks, dimension change, death/spectator or disconnect stops the job. Ownership uses existing server block-entity tags, and replies update only already-known client snapshots. Requests/results use a separate versioned channel so older companions keep normal features and cannot start unsupported scans.

The user's other follow-ups are included: inventory widgets track current geometry separately from their 50 ms data cache, focused Stow text fields have a vertical append caret and one correctly placed hint, and storage rows are denser (58/54 GUI pixels) with up to three readable columns. Visible item stacks/count labels are prepared on refresh, avoiding repeated icon/count reconstruction for the larger page. Vanilla/other-mod EditBoxes retain their original append cursor, while native selection, editing and IME paths remain intact.

The exact delivery pair passes **85 area/camera/UI checks** (`area-claim-probe/output-visual-final.log`, `result.txt`), the client passes **770 established regressions** (`full-pass-area-final/output-delivery.log`, `full-result.txt`) and **21 effects/layout/no-companion checks** (`effects-overlap-area-final/output-delivery.log`, `result.txt`), totaling **876**. Final camera, actual review, focused vertical caret, compact normal/selection and narrow claim-screen screenshots were inspected. A screenshot capture initially read the previous frame; final caret/review evidence waits for the changed UI to render. The placement timeout was traced to a synthetic fixture hit before the server-built support block arrived; the fixture now waits for support updates, and the exact uninstrumented regression run passes. Build, 454 bilingual keys, artifact separation, canonical README alignment and whitespace checks pass. SHA-256 and limits are in `PERFORMANCE.md`. Initial fixture issues included an unassigned local camera ID (fixed in production) and a corner aimed at air hitting the correct floor block (test marker corrected). ## Build

Use JDK 25 and the included Gradle wrapper. Run `./gradlew build` on Linux/macOS or `.\gradlew.bat build` in Windows PowerShell. Import the repository root as a Gradle project in your IDE; `runClient` opens the development client.

The pinned versions are Minecraft 26.3, Fabric Loader 0.19.5, Fabric API 0.161.0+26.3, Cloth Config 26.3.159, optional Mod Menu 21.0.0, Loom 1.17.21 and Gradle 9.6.0. Minecraft 26.3 uses unobfuscated names, so there is no mappings dependency.

## Version checks

`VersionChecker` runs network work on daemon threads and adds the chat notice on the client tick thread. It checks published stable client releases for the running Minecraft version. GitHub releases must include the matching client JAR. Modrinth versions must list the matching Minecraft version and Fabric. CurseForge uses CFWidget's public file metadata, filtered by release type, Fabric and Minecraft version.

The request URLs are fixed public endpoints. Download links are constructed for the three official project pages. No credentials or game data are sent. `lastNotifiedVersion` is saved only in the player's local settings so reconnecting or restarting does not repeat the same notice.
